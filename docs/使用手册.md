# minime 使用手册

> 面向「想马上用起来」的人。不需要懂采集、流水线、SQLite。
> 全流程只有一件事：**先让它把你的东西收进来，然后打开面板开始用。**

---

## 0. 三十秒版

```bash
minime web          # 打开 http://127.0.0.1:8765/
```

> 还没安装？先看第 2 节「第一次跑起来」；装好后第一次要先跑一次 `minime setup`，把数据收进来。

打开后看三件事就够了：

| 我想干什么 | 点哪里 |
|---|---|
| 问它问题（基于我的知识回答） | 顶栏 **对话** |
| 看它收了多少、洗干净多少、归纳到哪了 | 顶栏 **处理进度** |
| 翻我沉淀下来的知识 | 顶栏 **知识浏览** |

第一次用，建议顺序：**处理进度 → 点「完整更新」→ 等跑完 → 去「对话」问一句。**

## 1. 它到底是干什么的

你在 Trae 里干的活（聊天、改文件、写的笔记），minime 会：

```
采集  →  清洗  →  归纳  →  回答问题
(收集)   (拆成条目)  (提炼结论)   (对话/MCP)
```

- **采集**：读 Trae 的会话快照、云端会话、记忆文件、你指定的本地目录、Obsidian，以及 WorkBuddy / WorkBuddy AI、Qoder 的本地会话与豆包导出的会话。
- **清洗**：把一大段对话/文件拆成一条条可检索的「知识原子」，打上项目、技术、场景等标签。正文全文入库，不按长度截断；启用 LLM 时，超过「长文摘要阈值」的条目会生成摘要（每轮有上限，结果按内容缓存），未启用时摘要取正文前 160 字。
- **整理**：每次清洗后自动执行一次——`valid_until` 到期的知识归档，长期无反馈的低价值事件按保留期归档，同类型、同作用域且标题与正文都高度相近的条目只保留一条，其余标记为「已取代」。只改状态，不删除数据。
- **归纳**：用本地大模型把「改了 3 个文件」提炼成「为什么这么改、约束是什么」。
- **使用**：面板里问它，或者把它接进 Trae 当 MCP 工具，让 AI 直接调用你的经验。
- **检索**：关键词（中文二元组 + 全文索引）与语义向量混合打分。向量检索默认开启，只需在设置页「向量检索」填 OpenAI 兼容的 embedding 接口地址与模型（如本地 Ollama 的 `bge-m3`）；接口不可达或超时会自动降级为纯关键词检索，不影响使用。换模型后需重新清洗一次以生成新向量。
- **回答方式**：设置页「回答方式」一个开关决定问答链路——**大模型作答**（默认）：模型理解问题并归纳证据作答，检索同时启用向量；**关键词规则作答**：直接摘录命中的知识、不调用模型，检索只用关键词，模型不可用时也能用。命令行等价于 `minime set answer.mode llm|rules`。
- **存储与清理**：本地目录单轮最多采集 20000 个文件（设置页「本地数据源 → 单轮最多采集文件数」，达到上限会在采集统计里标 `truncated`）；原始归档每个来源只保留最近 3 个版本、检索与引用日志保留 180 天，超期在每次清洗后自动清理。三项都可改（`consolidate.raw_keep_versions`、`feedback.usage_retention_days`），设成 0 表示永久保留。清理只删历史副本与日志，不影响已入库的知识正文。
- **数据放在哪**：程序目录只放代码，知识库、配置、日志、资源包统一放在数据目录——macOS 是 `~/Library/Application Support/minime`，Windows 是 `%LOCALAPPDATA%\minime`，Linux 是 `~/.local/share/minime`。想换位置就设置环境变量 `MINIME_HOME`。源码版升级到 pipx 版时，用 `minime migrate --from <旧目录>` 把旧数据搬过来；装好之后升级/替换程序都不会丢数据。

它不会改你任何原始数据，只读。

## 2. 第一次跑起来

### 2.1 确认环境

```bash
minime doctor
```

看到一串 `✓` 就说明能用。常见的 `✗` 是 `adapter.obsidian`（本机没装 Obsidian）或 `adapter.doubao`（未导出会话/未授权读取应用容器），**不影响其他功能**，可以忽略。豆包的完全磁盘访问权限是授给「运行 minime 的程序」，不是给豆包，步骤见 [6.5 豆包](#65-豆包doubao)。

如果提示 `minime: command not found`，说明还没装成命令。推荐用 pipx 装一次（独立环境，升级不影响数据）。

minime 已发布到 Repsy。公开库一条命令装好，不需要 token：

```bash
pipx install \
  --index-url "https://repo.repsy.io/tengwang/pypi/simple/" \
  --pip-args="--prerelease=allow" minime

# MCP / 云端采集 / 向量加速 三个可选依赖只在上游 PyPI，单独注入
pipx inject minime mcp cryptography numpy
```

如果返回 `401 Unauthorized`，说明仓库仍是 **Private**（Repsy 默认私有）：到仓库设置把 Visibility 改成 **Public**，或改用带 token 的地址：

```bash
pipx install \
  --index-url "https://<用户名>:<token>@repo.repsy.io/tengwang/pypi/simple/" \
  --pip-args="--prerelease=allow" minime
```

锁版本时用 `minime==0.1.0rc7`，可以省掉 `--prerelease=allow`。也可以从本地仓库装：`pipx install "/path/to/minime[full]"`。

Windows 上命令相同（`minime`），面板地址也是 `http://127.0.0.1:8765/`；定时采集会自动装成计划任务。

从源码版迁过来时，把旧目录的数据搬进数据目录：

```bash
minime migrate --from /path/to/old/minime
```

源码方式也可以直接跑（在 minime 源码目录下）：

```bash
.venv/bin/python run/minime.py doctor
```

数据目录与代码目录是分开的：知识库、配置、日志在

- macOS：`~/Library/Application Support/minime`
- Windows：`%LOCALAPPDATA%\minime`

想换位置就设 `MINIME_HOME`。`minime status` 会直接告诉你当前用的是哪个目录。

### 2.2 首次构建

```bash
minime setup
```

这一步会采集 + 清洗 + 建图谱 + 画像，第一次跑几分钟。跑完再 `minime status` 看一眼：

```
知识 1346 条 · 实体 748 个 · LLM 归纳产物 89 条
```

## 3. 打开面板

```bash
minime web
```

浏览器访问 **http://127.0.0.1:8765/**

> 端口默认 8765；如果改过 `web.port` 或设了 `MINIME_WEB_PORT`，以 `minime status` 里显示的端口为准。

面板有 11 个页签，按你会用到的频率排：

| 页签 | 干什么 | 什么时候用 |
|---|---|---|
| **对话** | 问它问题，多轮追问，回答带来源 | 最常用 |
| **处理进度** | 进度条、待处理数量、后台任务 | 想知道「还剩多少活」 |
| **知识浏览** | 按项目/技术/类型筛选知识 | 想翻具体条目 |
| **知识图谱** | 项目-技术-概念的关系图，可拖拽 | 想看全局结构 |
| **能力画像** | 8 个维度的能力评分 | 想了解自己 |
| 工作区 | 哪些工作区被采了、多少会话 | 排查「为什么没采到」 |
| 采集源 | 每个源的周期、状态、手动触发 | 某个源报红 |
| 数据源包 | 导出/导入知识包 | 想分享或合并 |
| 运行日志 | 所有操作记录，可按级别/关键词过滤 | 出问题 |
| 设置 | 配置表单 | 改模型、改周期 |
| 归档 | 原始数据存放位置与大小 | 查底层 |

## 4. 最常用：对话

### 4.1 怎么问

顶栏 → **对话** → 底部输入框输入问题 → **Enter 发送**（Shift+Enter 换行）。

回答下方会列出 `[1] [2]` 来源条目，**点一下就能看那条知识的完整原文**。

### 4.2 它会怎么回答

它**只依据你的知识库**回答，所以会出现两种情况：

- **知识库里有** → 直接给结论 + 标注 `[1]`，例如：
  > macOS 兼容需遵循：路径必须用 `path.join()`，禁止字符串拼接 [1]；仅在 macOS 验证过时必须标注 Windows/Linux 未验证 [1]。
- **知识库里没有** → 会先说「知识库里没有这条」，然后给通用经验并明确标注「（通用经验）」。

这个设计是为了让你一眼分清「这是我的经验」还是「AI 猜的」。

### 4.3 多轮对话与历史

- **同一会话内**可以连续追问（「那依据是什么？」），它记得前 6 轮。
- **左侧列表**是历史会话，点一下切回去，内容都在。
- 悬停会话项，点右侧 `×` 可删除；右上「重命名」可改标题。
- 会话标题自动取第一个问题，URL 带 `?view=chat&session=xxx`，刷新不会丢。

### 4.4 命令行版（可选）

```bash
minime chat "我有哪些架构决策？"           # 新开一个会话问
minime chat --session S18e10c207b6f "那依据是什么？"   # 续上次的会话
minime chat --list                        # 历史会话
minime chat --show S18e10c207b6f          # 看整段对话
```

## 5. 让它越来越好用

知识库不是死的，有两个地方要维护：

### 5.1 补归纳（提升回答质量）

打开 **处理进度**，看「待处理」：

- 不是 0 → 点 **「立即归纳一批」**。每批处理 12 轮，约 8 分钟。
- 想一次跑完：点 **「归纳全部」**，一次处理所有待处理轮次（耗时较长，可随时在顶栏停止）；命令行 `minime llm --all`。
- 想自定义一批的数量：`minime llm --run 50`（后台跑，可关终端）。

进度条含义：`已处理轮次 / 有实质改动的轮次`。之所以按轮次而不是按条数，是因为一轮可能提炼出 0 条（琐碎改动）也可能 3 条。

### 5.2 给反馈（让好知识浮上来）

知识浏览页每张卡片底部有 **采用 / 引用 / 不相关**，点击后卡片上会显示最近一次反馈与累计次数：

- **采用 / 引用** → 该条反馈分提高，以后更容易被检索到
- **不相关** → 反馈分降低并轻微降低可信度；连续多次（默认 2 次）进入「已降权」，不删除，正常命中不足时仍会召回，可在左侧「状态 → 已降权」点「恢复」

对话里被引用的知识也会自动 +。这是「越用越好用」的机制，用得越多越准。

## 6. 让它采到你真正想要的东西

### 6.1 加自己的目录

默认采集 Trae、WorkBuddy / Qoder 相关数据（豆包需先导出或授权读取）。你自己的笔记/文档要手动加：

设置页 → **本地数据源** → **采集目录**，每行一个路径：

```
~/Documents/notes
~/work/my-project
```

保存后下次采集自动生效；想立刻采：`minime collect --force`。

### 6.2 Obsidian

设置页 → **Obsidian** → **vault 目录** 填你的库路径。它会解析 frontmatter、`[[双链]]`、`#标签`。

隐私开关：在某篇笔记的 frontmatter 里加 `private: true`（或 `minime: ignore`），这篇**整篇不被采集**。

### 6.3 WorkBuddy / WorkBuddy AI

无需配置：默认扫描 `~/.workbuddy-ai` 与 `~/.workbuddy`，采集会话 JSONL、长期记忆（`memory/*_memory.md`）和已填写的身份字段（USER / IDENTITY / SOUL）。收到消息里的系统注入上下文会自动剥离，只保留你真正输入的内容。

如果数据在自定义目录，到设置页 → **AI 助手数据源 → WorkBuddy 目录** 填写；保存后 `minime collect --force` 立即生效。

### 6.4 Qoder

无需配置：默认读取 `~/Library/Application Support/com.qoder.app.stable/main.sqlite`，采集：

- 会话标题、工作区、模型、时间（`chat_sessions`）
- 消息正文（`chat_session_messages.payload_json` 里的纯文本，工具调用与结果跳过）
- 每轮改动的文件清单（`turn_file_change_files`）

Qoder 运行中也能只读采集，WAL 会一并读取，不会修改原始数据。数据在自定义目录时，到设置页 → **AI 助手数据源 → Qoder 目录** 填写；Windows 自动扫描 `%APPDATA%\Qoder`，Linux 扫 `~/.config/Qoder`。

### 6.5 豆包（Doubao）

豆包桌面端暂未开放完整本地接口，minime 支持三种来源：

1. 豆包「设置 → 数据导出」得到的 JSON / JSONL
2. 本地 SQLite 消息表（自动识别消息/会话表）
3. 导出的 Markdown / TXT

把导出文件放到一个固定目录（例如 `~/Documents/doubao-export`），到设置页 → **AI 助手数据源 → 豆包导出目录** 填该目录即可。**这条路不需要任何系统权限，推荐大多数人使用。**

#### macOS 直接读取豆包数据：完全磁盘访问权限

只有想直接读豆包应用容器、且会话落在本地 SQLite 时才需要这一步。注意两点：

- **不是给豆包授权，而是给读取豆包数据的程序授权**——豆包自己当然能读自己的数据，受限的是 minime / 终端。
- 完全磁盘访问权限只解决「能不能读文件」，不解决「文件格式能不能解析」。豆包聊天正文主要存在 **IndexedDB** 里，minime 当前不直接解析 IndexedDB；如果 `doctor` 仍提示「发现 IndexedDB 缓存」，请改用上面的导出目录方式。

操作步骤：

1. 打开 **系统设置 → 隐私与安全性 → 完全磁盘访问权限**
2. 点 `+`，添加你实际运行 minime 的程序：
   - 在 Terminal 里跑：添加 **Terminal**
   - 在 iTerm 里跑：添加 **iTerm**
   - 在 Trae 的内置终端里跑：添加 **Trae**
3. 打开对应开关，然后**完全退出并重新打开**该程序（只关窗口不够）
4. 验证：

```bash
minime doctor
# 或
minime collect --force
```

`adapter.doubao` 变绿、且「采集源」里能看到会话数，就说明授权生效。

两个常见坑：

- **定时任务不继承终端授权**：`minime install` 注册的 launchd 任务由系统直接启动 Python，在终端里授权 Terminal 对它无效。定时采集豆包建议直接用上面的「导出目录」方案，不需要权限。
- **授权对象弄错**：把豆包加进完全磁盘访问权限不会让 minime 读到数据；必须添加「读取方」。

如果不想授权、也不想导出，可以关闭豆包采集源；它显示红色不会影响 Trae、WorkBuddy、Obsidian 等其他源。

### 6.6 调整采集频率

设置页 → **定时采集 · 各源周期**，每个源各自填秒数。改完**不用**重装定时任务。

只有改「定时触发间隔」才需要 `minime install` 重新注册。macOS 会把任务装进 launchd，Windows 装成同名计划任务（`ai.minime.collect`），命令一样；Linux 没有系统定时任务，用 `minime watch` 常驻。

## 7. 接进 Trae（进阶）

让 Trae 里的 AI 直接调用你的经验库：

```bash
minime mcp --http        # HTTP 模式，跨 AI 共享
# 然后在 Trae 的 MCP 配置里填 http://127.0.0.1:8791/mcp
```

或者在 Trae 的 MCP 配置里用 stdio：

```json
{
  "mcpServers": {
    "minime": {
      "command": "minime",
      "args": ["mcp"]
    }
  }
}
```

> 命令不在 PATH 里时，把 `command` 换成 Python 解释器绝对路径，`args` 换成 `["<minime 目录>/mcp_server/server.py"]`。

接上之后，你在 Trae 里可以直接说「用 minime 查一下我以前怎么处理这个问题的」，AI 会调用 `minime_recall` / `minime_decide` / `minime_chat`。

18 个工具，最常用的 4 个：

| 工具 | 用途 |
|---|---|
| `minime_decide(question)` | 依据你的历史经验做决策建议 |
| `minime_recall(query)` | 检索知识 |
| `minime_chat(question, session_id)` | 多轮问答 |
| `minime_troubleshoot(symptom)` | 查排障经验 |

## 8. 常见的「咦？」

**Q：处理进度里的待处理一直不动？**
定时任务只做采集和清洗，**归纳是手动的**（LLM 单轮约 40 秒，放进定时会长期占着）。去点「立即归纳一批」或「归纳全部」，或 `minime llm --run 20` / `minime llm --all`。

**Q：问了问题，它说「知识库里没有」？**
两种可能：① 相关内容还没归纳（去看进度）；② 该内容确实没被采集到（去看「采集源」和「工作区」）。

**Q：某个采集源是红的？**
点进「采集源」，红行下面会直接写下一步该做什么。也可以 `minime doctor` 看详情。

**Q：豆包采集源是红的，提示 Operation not permitted？**
这是 macOS 的隐私保护，不是豆包坏了。两种解决方式：
1. **推荐**：豆包导出会话文件，放到固定目录，在设置页「AI 助手数据源 → 豆包导出目录」填该目录（无需权限）。
2. 直接读取应用容器：给**运行 minime 的终端/Python** 授予完全磁盘访问权限，**不是给豆包授权**；授权后完全退出并重开终端。注意这只对本地 SQLite 消息库有效，豆包正文若在 IndexedDB 仍需用方式 1。定时任务（launchd）不继承终端授权，建议用方式 1。详见 [6.5 豆包](#65-豆包doubao)。

**Q：知识库被清空了？**
不会真丢——原始归档和归纳结果在持久层。`minime restore` 可完整重建，不用重新采集。

**Q：升级 / 换电脑会不会丢知识？**
不会。数据和代码分开存：知识库、配置、归档、日志都在数据目录。`pipx upgrade minime` 或换安装目录都不影响；换电脑把整个数据目录拷过去（或在新机器上设同一个 `MINIME_HOME`）就能接着用。`config.json` 含密钥，备份时注意保管。

**Q：源码版换成 pipx 版，数据怎么搬？**
先装好 pipx 版，再执行 `minime migrate --from <旧目录>`：会把旧目录里的 `store/` 和 `config.json` 搬到数据目录。目标已有知识库会拒绝执行；只想补搬缺失的归档/日志时加 `--merge`。

**Q：日志在哪？**
数据目录下 `store/logs/minime.jsonl`，或面板「运行日志」页；`minime logs -f` 可跟随。

**Q：改了代码/配置没生效？**
`minime status` 会检测「代码已更新但服务在跑旧版本」，提示你重启 `minime web`。配置项里 `web.*` 要重启面板，`schedule.*` 要 `minime install`，`collect.*` 下次采集生效，`minime set` 保存时会直接告诉你。

**Q：想反馈 bug？**
`minime diag` 生成脱敏诊断包（自检 + 进度 + 配置 + 日志，密钥已替换成 `***`），直接把 zip 发出去就行。

## 9. 一页命令速查

```bash
# 日常
minime web                      打开面板（主要就用这个）
minime status                   一眼看全：采集/归纳/定时/服务
minime chat "问题"              命令行问一句

# 维护
minime update                   增量更新（采集+清洗）
minime llm --run 20             后台归纳一批
minime llm --all                归纳全部待处理轮次
minime collect --force          立刻全部重采
minime doctor                   自检

# 配置
minime config                   看当前生效配置
minime set llm.enabled true     改一项配置
minime set collect.local.roots ~/notes

# 数据
minime restore                  重建知识库（不重新采集）
minime diag                     导出脱敏诊断包
minime pack export              导出可分享的知识包
minime migrate --from ~/code/minime   把旧源码目录的数据搬到数据目录

# 定时
minime install                  安装每 30 分钟定时采集（macOS launchd / Windows 计划任务）
minime uninstall                移除定时任务（数据保留）
```
